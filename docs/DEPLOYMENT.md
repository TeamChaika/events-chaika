# Публикация на Timeweb

Репозиторий: https://github.com/TeamChaika/events-chaika, ветка `main`.
Целевой домен: `event.chaika.team`.

Для текущей SQLite-реализации подготовлена установка на отдельный Cloud Server с Docker Compose. База и загруженные афиши хранятся в постоянном томе `chaika-events_app_data`. Обновление образа не удаляет этот том. Файл `compose.production.yml` предназначен для Cloud Server; [Timeweb App Platform запрещает пользовательские volumes](https://timeweb.cloud/docs/apps/deploying-with-docker-compose), поэтому туда эту конфигурацию без смены хранилища переносить нельзя.

На 19 сентября 2026 код опубликован в GitHub, Docker-образ проверен локально. Timeweb отклонил создание серверов на тарифах 2575 (`no_free_node`), 6769 и 6767 (`servers_is_run_out_error`); ни один из этих серверов не создан. Публичная публикация ожидает выбора другого тарифа или существующего сервера. A-запись и TLS домена ещё не настроены.

## Первая установка

Ubuntu 24.04, Docker Engine и Compose v2. Разрешённые входящие порты: 22, 80, 443. Сервис API не публикует свой порт 8787 наружу; HTTPS и сертификаты обслуживает Caddy.

1. Клонировать репозиторий в `/opt/events-chaika`.
2. Создать `/etc/chaika-events/app.env` с правами 600, задать разные случайные `ADMIN_PASSWORD` и `SCANNER_PASSWORD` от 16 символов. На первом размещении `QRM_MODE=disabled`, `DELIVERY_ENABLED=false`. Не переносить локальную демо-БД.
3. Направить A-запись `event.chaika.team` на IPv4 сервера. Проверить отсутствие конфликтующих A/AAAA/CNAME; существующие TXT/MX не менять.
4. Из папки проекта выполнить `docker compose -f compose.production.yml up -d --build --wait --wait-timeout 180`.
5. Проверить HTTPS, `/api/health`, `/api/config`, вход в `/admin` и `/checkin`, главную страницу и 3D-луну.

Админка: `https://event.chaika.team/admin`. Контроль входа: `https://event.chaika.team/checkin`. Production работает без демо-входа и без симуляции оплаты.

## Обновление

После push в `main` выполнить на сервере `sh /opt/events-chaika/deploy/update.sh`. Скрипт создаёт согласованную копию SQLite, выполняет только fast-forward обновление Git и пересобирает контейнер. Сохранить SHA из вывода и проверить здоровье сервиса. Автодеплой не настроен.

Нельзя выполнять `docker compose down -v`: ключ `-v` удаляет данные. Резервные копии SQLite создаются в том же томе `/app/data/backups`; это страховка обновления, а не защита от потери сервера. Перед открытием реальных продаж нужны отдельные внешние резервные копии базы и папки media.

Для проверки сохранности данных после первого запуска создать скрытое тестовое мероприятие в админке, пересоздать контейнер app без удаления тома и проверить, что мероприятие осталось.

Публичная оплата и доставка включаются только после настройки соответствующих сервисов из README и отдельной проверки реальной цепочки.
