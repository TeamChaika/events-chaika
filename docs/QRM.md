# Контракт QRM

Проверен 19.09.2026 по официальной [документации v2](https://docs.qrmanager.ru/docs/v2) и [Swagger JSON](https://docs.qrmanager.ru/static/merged_swagger-2.json).

- Sandbox origin в спецификации: `https://app.devwapiserv.qrm.ooo`. Live origin не угадывается: задаётся владельцем терминала в `QRM_API_BASE_URL`.
- Авторизация: `X-Api-Key`, только сервер. Sandbox/live имеют разные имена переменных.
- `GET /users/check-api-key/`: проверка API key, merchant_id, B2C, срока терминала. Live требует совпадения с `QRM_EXPECTED_MERCHANT_ID`.
- `POST /operations/qr-code/`: `sum`, `price`, `amount` — **копейки**, `count` — количество. Заказ сначала сохраняется в PostgreSQL (локально — SQLite). В номенклатуре используется документированное значение `payment_method=4`. Финальные фискальные настройки должен подтвердить владелец кассы.
- TTL QR задан 15 минут. Ответ содержит `results.operation_id`, `qr_link`, `payment_page_link`. Ссылки допускаются только по HTTPS на доменах QRM/НСПК.
- POST-идемпотентность провайдера не документирована. Поэтому после неизвестного исхода заказ остаётся `unknown`, а создание не повторяется автоматически. Нужна сверка с кабинетом QRM; автоматическая привязка операции без ID не реализована.
- Callback: `/api/webhooks/qrm/{saved-order-id}/{random-secret}`. Это локальный секрет корреляции, **не подпись QRM**. Тело callback не является подтверждением оплаты и не может заменить сохранённый operation ID.
- `GET /api/v2/sse-operations/{id}/qr-status/`: SSE, также поддержан JSON при таком Content-Type. Поток ограничен временем и 64 КБ, соединение закрывается после чтения события.
- `operation_status_code`: 3 создан, 4 в процессе, 5 оплачен, 6 отменён, 8 просрочен, 0 таймаут ожидания. Для выпуска нужен код 5 и точное `operation_sum === order.total`.
- Ответ статуса не содержит отдельного merchant/currency: получатель проверен при создании терминалом, статус относится к сохранённому UUID. Отдельная проверка отсутствующих в контракте полей не заявляется.
- Worker читает сохранённые незавершённые операции после рестарта: до 4 операций за проход, не чаще 30 секунд на операцию, максимум 150 попыток. После лимита — ручная кнопка сверки. Неизвестный исход без operation ID не переотправляется.
- Выпуск билетов и очередь уведомлений транзакционны и идемпотентны. `paid` не откатывается запоздалым событием. Поздняя оплата после освобождения мест при нехватке вместимости получает `paid_review` и отдельное уведомление организатору без автоматического переполнения зала.
- Автоматические возвраты, частичные возвраты, отмена билетов после возврата и разрешение `paid_review` пока не реализованы — требуют отдельного операционного сценария перед боевым запуском.

Доставка реализована по [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage), [SMS Aero API v2](https://smsaero.ru/integration/documentation/api/) и SMTP через Nodemailer. Проверка локальных адаптеров не является подтверждением реальной оплаты или доставки.

## SMS Aero

Контракт проверен 19.09.2026. Сервер использует `https://gate.smsaero.ru/v2`, HTTP Basic Auth в заголовке, POST form-urlencoded; секреты никогда не включаются в URL. Настройки: `SMSAERO_EMAIL`, `SMSAERO_API_KEY`, `SMSAERO_SIGN`, общий переключатель `DELIVERY_ENABLED=true`.

- `/auth` проверяет доступ без отправки. Кнопка проверки доступна только администратору.
- `/sms/send` передаёт один номер, имя отправителя и ссылку на все билеты оплаченного заказа. СМС для demo/sandbox-заказов не отправляются.
- `/sms/testsend` предназначен для бесплатной проверки формата без настоящего сообщения; он не проверяет достаточность баланса.
- ID и код статуса сохраняются в очереди. Принятие сообщения (`submitted`) отличается от доставки (`delivered`, код 1); коды 2/6 — отказ доставки. Коды 0/3/4/8 продолжают ожидание.
- `/sms/status` опрашивается сервером с увеличением интервала до 15 минут, максимум 100 попыток. Проверяются ID и номер получателя. Перезапуск приложения не теряет очередь.
- Неопределённый результат отправки не повторяется автоматически. Если ID уже известен, администратор может возобновить только сверку статуса; подтверждённый отказ можно отправить повторно вручную. Повторная отправка доставленного сообщения запрещена.

Закрытый файл `.env.integrations.local` исключён из Git и Docker. `npm run integrations:check` загружает его явно и проверяет QRM/SMS Aero без платежа или сообщения. В production настройки передаются через переменные Timeweb Apps, а не через этот файл.
